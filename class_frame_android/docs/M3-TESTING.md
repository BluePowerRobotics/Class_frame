# M3 测试指南（调度与生命周期）

## 1. M3 交付内容

| 能力 | 实现 |
| --- | --- |
| 放学隐藏 | 当天最后一节下课 **10 分钟**后隐藏悬浮层（移除窗口，保留前台服务） |
| 课前重现 | **次日首节课开始前 1 小时**重新显示（不特殊处理"全天无课"的日子） |
| 下一次唤醒 | `ScheduleEngine` 计算下一次切换时刻；进程存活时用 `Handler` 精确触发，同时向 `AlarmManager` 排一个 `setExactAndAllowWhileIdle` 作为兜底 |
| Doze 与权限 | Android 12+ 检查 `canScheduleExactAlarms()`，未授予时退化为 `setAndAllowWhileIdle` 并继续运行 |
| 时钟校正 | `时间偏移（秒）`在"校正后的时间"里判断，触发时刻换算回真实时钟 |
| 系统事件 | 息屏停心跳、亮屏重新评估；时间/时区变化后重算并重排 |
| 开机 | `BOOT_COMPLETED` 拉起服务后立即按调度评估显示或隐藏；服务 `START_STICKY` |
| 兜底 | 心跳每 30 秒复核一次调度，防止漏触发 |

## 2. 真机验证记录（Android 9 / API 28 测试机）

用 `时间偏移（秒）` 把程序时间推到不同时段验证，无需等待真实时间。

| 场景 | 程序时间 | 结果 | 证据 |
| --- | --- | --- | --- |
| 白天放学前后 | 21:25 | 显示中，下一次切换 = 21:40 隐藏 | 日志 `schedule: shown -> hide @ 09-20 21:40:00`；`dumpsys alarm` 中有 `when=2026-09-20 21:40:00` 的 RTC_WAKEUP 闹钟 |
| 放学 10 分钟后 | 21:45 | 悬浮层已隐藏（0 个窗口） | 日志 `schedule: hidden -> show @ 09-21 05:50:00`；窗口列表中无 `class_frame_overlay` |
| 次日课前 1 小时之后 | 次日 06:15 | 悬浮层自动显示 | 日志 `schedule: shown -> hide @ ...`；窗口列表恢复为 2 个 `class_frame_overlay` |

时间偏移换算验证：程序时间 06:10（首节课 07:10 前 1 小时）对应真实时钟 05:50，
闹钟 `when=2026-09-21 05:50:00` —— "校正后的时间判断 + 真实时钟排程"这条链路正确。

## 3. 与 Python 版的差异（设计如此）

- Python 版放学 10 分钟后直接退出进程；Android 版改为**隐藏悬浮层 + 保留服务与排程**，
  才能做到次日自动重现。
- 息屏时心跳停止（Python 版是常驻 60Hz 循环），功耗与占用更低。

## 4. 手动验证建议

1. 把 `config.json` 的 `时间偏移（秒）` 改到"放学 10 分钟后"，重启应用 → 悬浮层消失，
   通知文本变为"悬浮层已关闭"
2. 再改到"次日课前 1 小时之后" → 悬浮层自动出现
3. 观察日志：`adb logcat -s ClassFrame`，每次评估打印一行
   `schedule: shown/hidden -> show/hide @ 时间`
4. `adb shell dumpsys alarm | grep -A2 bluepowerrobotics` 可确认闹钟是否排上
