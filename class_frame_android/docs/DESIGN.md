# 技术方案

本文档记录架构设计与关键实现决策，重点是"无变动不渲染"的调度模型，以及移植 Python 版时容易踩坑的地方。

## 2. 调度模型（核心）

### 2.1 为什么不用常驻循环

Python 版是 60Hz 大循环，同时做四件事：状态判定、布局、绘制、窗口位置动画。搬到 Android 后必须拆开：

- **状态判定**不需要轮询。课表时间是已知的，下一节课开始/结束、提示到期、放学 +10 分钟隐藏、次日首课前 1 小时重现，都是可精确计算的时间点。
- **布局**只在"内容或尺寸变化"时执行一次。
- **绘制**只在脏标记置位时执行。
- **窗口动画**只在动画未收敛时执行。

### 2.2 唤醒来源

| 来源 | 触发时机 | 实现 |
| --- | --- | --- |
| 状态边界 | 上课开始/结束、提示到期、放学 +10min、次日重现 | 进程存活用 `Handler.postAtTime`；跨休眠/跨天用 `AlarmManager`（Doze 下用 `setExactAndAllowWhileIdle`） |
| 显示节拍 | 倒计时 mm:ss、center 时钟 HH:MM:SS、进度条 | 1Hz 对齐秒边界（见 2.5） |
| 触摸 | 按下/拖动/抬起 | `onTouchEvent` |
| 系统事件 | 时间/时区变化、屏幕亮灭、开机、配置导入 | 广播接收器 |
| 帧回调 | 仅在有动画或处于交互期 | `Choreographer.postFrameCallback` |

进程存活时用 `Handler`（开销最低），进程被杀或深度休眠时用 `AlarmManager` 兜底；两者由 `ScheduleEngine` 统一维护"下一次唤醒时间"，重启后可从持久化恢复。

### 2.3 渲染门控三档

| 档位 | 进入条件 | 行为 |
| --- | --- | --- |
| Idle | 无动画、非交互、无脏标记 | 不注册 `Choreographer`，不 `invalidate`，不调用 `updateViewLayout` |
| 显示节拍 | 有倒计时/时钟/进度条可见 | 1Hz 对齐秒边界，仅重绘变化的部分 |
| 交互/动画 | 按下/拖动中，或动画未收敛，或处于交互后保持期 | 按"最高帧率"渲染，几何与内容同步更新 |

退出交互后先进入"保持期"（默认 500ms，可配置），再回落；但**只要动画未收敛就继续留在高帧率档**，不受保持期限制——否则动画会在低帧率下走完，出现顿挫。

### 2.4 帧率语义

- 最高帧率：`Choreographer` 只能跟随 vsync，要限制到 N fps 必须自行跳帧（时间累加器），不能靠系统节流；档位只提供至 60。
- 逻辑帧率：动画期间的评估频率，把状态评估与触摸采样分离，便于在 4 代机上单独降档。
- 屏幕上限：目标帧率同时不超过 `Display.getRefreshRate()`；希沃一体机多为 60Hz。

### 2.5 1Hz 秒边界对齐

```java
long now = SystemClock.elapsedRealtime();
long delay = 1000 - (now % 1000) + 8;   // +8ms 保证落在秒边界之后
handler.postDelayed(tick, delay);
```

要点：

- 显示值每次都从时钟重算（`left_sec = ends[i]*60 - now_sec`），**不做累加**，避免 Doze、调度延迟、改时间造成漂移。
- 调度用单调时钟 `elapsedRealtime()`，显示值用墙钟；收到 `ACTION_TIME_CHANGED` / `ACTION_TIMEZONE_CHANGED` 后立即重绘并重排。
- `fmt_mmss` 是向下取整，tick 早于边界会重复渲染同一秒，故安排 +8ms。
- 屏幕熄灭（`ACTION_SCREEN_OFF`）时注销 ticker，亮起时先立即重绘一次再接回 1Hz，夜间零开销。

### 2.6 进度条策略

40 分钟的课在 1080px 宽度上每秒移动约 0.45px，放学 10 分钟倒计时约 1.8px/s，1Hz 足够。取消原计划的 10fps 设置项。

- 进度条几何按比例直接计算，**只在绘制最后一刻取整**；若每 tick 取整，会退化成"卡两秒跳一下"。
- 有文字（mm:ss / HH:MM:SS）时统一走 1Hz；纯进度条场景可选按"下一次整数像素变化"排期，收益有限，默认不做。

## 3. 弹性动画与收敛判定

Python 的窗口位置动画递推：

```
speed = (now - prev) * 0.85
nxt   = 0.035*goal + 0.965*now + 0.55*speed
```

### 3.1 数学性质

令误差 `e = goal - now`、速度 `v`，可写成：

```
e_{n+1} = 0.965*e_n - 0.4675*v_n
v_{n+1} = 0.035*e_n + 0.4675*v_n
```

- 平衡点为 `e = v = 0`，即 **`now = goal`，没有稳态偏移**。原因是两个位置项系数之和恰为 1（0.035 + 0.965 = 1.0）。
- 特征根 `λ₁ = 0.9296`、`λ₂ = 0.5029`，均为正实根且落在 (0,1) 内：**单调收敛、无过冲、不振荡**。
- 主极点 0.9296 对应时间常数约 457ms（`refresh_isl` 实际以 30Hz 调用）。

### 3.2 收敛耗时（500px 跳变，实测仿真）

| 条件 | 30Hz | 60Hz |
| --- | --- | --- |
| 误差 < 1px | 87 帧 / 2.90s | 1.45s |
| 误差 < 0.5px | 96 帧 / 3.20s | 1.60s |
| 误差 < 0.1px | 118 帧 / 3.93s | 1.97s |

结论：500px 的跨区跳变需要约 3 秒才收敛到亚像素，因此"交互后保持高帧率"必须以动画收敛为准，而不是固定时长。

### 3.3 停止条件

Python 中唯一的显式停止是删除分支（误差 < 1.5px 时销毁窗口）；正常动画没有任何停止条件，靠 30Hz 循环无限更新，视觉上因为几何取整在误差 < 1px 后看不出变化。

Android 侧必须显式停止，规则：

1. 位置误差 `|e| < 0.5px` **且** 每帧速度 `|v| < 0.05px` → 判定静止。
2. 停止时执行 `now = goal` 吸附，并输出一次最终几何。
3. 注销帧回调，回到 Idle 档。
4. 几何更新前先比较取整后的整数坐标，只有发生变化才调用 `updateViewLayout`，避免 ±0.5px 边界的来回抖动。
5. 删除动画保留原有 1.5px 阈值，以维持原有手感。

加入速度条件的目的不是当前参数需要，而是为将来调参留余量：若把 0.035 调大让动画更快，仅按位置判定会在明显仍运动时冻结。

## 4. 悬浮窗管理

- **窗口粒度**：每个 island 一个独立窗口（主课表、下课倒计时），不用全屏透明窗口，避免 Android 12+ 不可信触摸拦截与穿透问题。
- **窗口类型**：API 26+ `TYPE_APPLICATION_OVERLAY`；API 24–25 `TYPE_PHONE`。
- **标记**：不可获焦、显示在其他应用之上，整体 alpha 0.92、黑底。
- **几何**：沿用 `SCREEN_GAP = 10`、`ISLAND_GAP = 30`；同 dock 的多个 island 居中排列；`edge_bar` 贴边（flush）。
- **屏幕尺寸**：使用 `WindowManager.getCurrentWindowMetrics()`（API 30+）与 `getRealMetrics()`（低版本）回退，处理旋转与分辨率变化。
- **拖动**：触摸事件天然跨窗口边界跟随，不需要 Python 的"全局指针轮询 + 合成 release"机制。

## 5. 文字测量与布局

Python 用 Tk 的 `winfo_reqwidth/reqheight` 做真实测量，Android 侧对应 `Paint.measureText` 与 `FontMetrics`：

- 单字字号规则需原样保留：横向 `fpx / len^0.5`，竖向 `fpx / len^0.7`。
- `wraplength` 对应 `StaticLayout` 或手动断行；提示行与课名保持不折行。
- **单位问题**：Tk 的正数字号是 point，受屏幕 DPI 影响；Android 有 px/dp/sp 三套体系。必须固定一套换算规则（建议把配置值视为 px 并按屏幕密度换算），并在多分辨率真机上校准。
- 时钟/日期/倒计时数字沿用"黑体"类无衬线字体，课表文字用所选圆体。

## 6. 字体管线

| 场景 | 方案 |
| --- | --- |
| 默认 | 内置开源圆体"资源圆体"（OFL 授权），替代微软幼圆；幼圆随 APK 分发存在授权风险 |
| API 29+ 系统字体 | `android.graphics.fonts.SystemFonts.getAvailableFonts()`（公开 API，已在 SDK 桩包核对），按 `getFamilyName()` 去重排序 |
| API 24–28 系统字体 | 遍历系统字体目录（`/system/fonts` 等），自行解析 TTF/OTF/TTC 的 name 表获取字体名；解析失败回退到文件名 |
| 用户字体 | 通过 SAF 导入 ttf/otf/ttc，复制到应用私有目录后加入列表 |

注意事项：

- TTC 在 API 26 以下只能取默认 index；API 26+ 可用 `Typeface.Builder#setTtcIndex`。
- 系统字体目录在部分设备上可能不可列出，必须整体 try/catch 并回退到内置字体。
- 悬挂字体文件较多，列表需要异步加载并缓存。

## 7. 数据兼容

- 所有 JSON 以 UTF-8 读写，保持中文原样（`ensure_ascii = false`）。
- `migrate_config` 需完整移植：旧位置写法 `a/b/c/f/u`、全局 `secondStyle`、`上课放大倍率`、缺失字段默认值。
- 桌面版写 config.json 时缩进并不统一（`save_settings` 用 2 空格，`save_schedule` 用 4 空格），Android 统一用 2 空格即可；已确认只要求桌面版能兼容读取，不要求逐字节一致。
- data.json 读取时过滤 tokens 长度不等于 `len(开始时间)+2` 的记录。
- 首次启动从 assets 释放默认 config.json 与班级模板。

## 8. 服务、权限与开机自启

- 前台服务常驻承载悬浮层；Android 14+ 声明 `foregroundServiceType`，Android 8+ 建通知渠道，Android 13+ 申请通知权限。
- `BOOT_COMPLETED` 接收器仅在"启用开机自启"为 true 时拉起服务；`RECEIVE_BOOT_COMPLETED` 权限为普通权限。
- 悬浮权限只能跳系统设置授予，无法静默获取；API 24–25 与 26+ 的窗口类型分支见第 4 节。
- 电池优化豁免走 `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`，未授予时仍可运行，但 Doze 下定时唤醒可能延迟，次日重现需以精确闹钟兜底。
- Android 12+ 精确闹钟需检查并引导授予"闹钟与提醒"权限。
- 服务被回收后由看门狗与持久化的"下一次唤醒时间"恢复。

## 9. 风险清单

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 字号单位换算与 Python 版不一致 | 不同机型布局跑版 | 固定换算规则 + 多机型校准 + 与 Python 截图比对 |
| 4 代机性能弱（2GB 内存） | 动画掉帧、卡顿 | 按需渲染、限制窗口数量、通过"最高帧率/逻辑帧率"设置自行降档（不提供独立低性能模式） |
| 系统字体目录不可读 | 字体列表为空 | 回退到内置字体与精选 family 白名单 |
| 悬浮权限/电池优化无法静默授予 | 首次使用需人工操作 | 引导页 + 状态检测 + 未授予时的降级提示 |
| 安卓通道受管控、无法安装 APK | 方案无法落地 | 部署前在真机验证（工厂模式开启未知来源） |
| 安卓侧定时关机/休眠 | 次日重现失败 | 精确闹钟 + BOOT_COMPLETED + 开机后自检 |
| 弹性动画不收敛导致常驻渲染 | 违背低功耗目标 | 收敛判定与吸附（第 3.3 节） |
