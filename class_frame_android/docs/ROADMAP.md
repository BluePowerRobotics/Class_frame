## M1 · 工程骨架与最小悬浮窗（6–9 人天）

交付物：可安装的 APK，授权后在屏幕上显示当天课表，重启设备后能自动出现。

> 状态：已完成并在 Android 9（API 28）真机上验收通过，明细见 `M1-TESTING.md` 第 9 节。
> 未覆盖：真实重启后的自启（设备不允许重启，改用广播模拟）；当前课节黄色高亮（测试日为周日，没有课节可高亮）。

| 1.2 | 应用骨架：Application、主题、字符串、占位图标；assets 放入默认 config.json 与班级模板 | 0.5 |

| 1.4 | `DayChangeRepository`（data.json + tokens 长度过滤）、`ClassTemplateRepository`（classes_frame 扫描）、`PrefsRepository`（开关与帧率设置） | 0.5–1 |

## 依赖与并行

- M1 是其他一切的前置，必须最先完成。
- M2 与 M4 中"课表 / 时间 / 参数"的 UI 可以并行开发，但都依赖 M1 的数据层。
- M3 依赖 M2 的渲染形态与 M1 的服务骨架。
- M5 需要真机，建议在 M2 完成后就开始穿插验证，不要全部压到最后。

## 开发期需要准备

1. 至少一台可安装 APK 的希沃真机（优先 4 代与 6/7 代各一台）；开发早期可先用 API 24 与 API 33 模拟器替代。
2. 签名密钥：若无，先用 debug 签名出测试包，正式包再建 release keystore。
3. 比对基准：若开发机上能运行 Python 版，则以截图逐状态对比；否则以代码逐行对照加真机目测为准。
