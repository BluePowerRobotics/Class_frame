# M2 测试指南（渲染与交互）

## 1. M2 交付内容

| 形态 | 触发条件 | 说明 |
| --- | --- | --- |
| `EDGE_TEXT` | 左/右/上方 + 文字样式 | 上方横排、左右竖排；`\|` 在竖排显示为破折号 |
| `EDGE_BAR` | 左/右/上方 + 第二样式 | 贴边纯进度条，长度按剩余比例从中间向外收缩 |
| `CENTER_SIMPLE` | 居中 + 文字样式 | 顶部进度条 + `HH:MM:SS` + 课表行 |
| `CENTER_EDITOR` | 居中 + 第二样式 | 日期行（`<` `>` 可切换）+ 课表行 + 候选网格（每行 6 个） |
| `PROMPT` | 上课后前 N 秒 | 上方为"提示词在上、课名在下"，左右为并排，均为黄色 |
| `COUNTDOWN` | 课间 / 放学 | 独立窗口；上方单行 `mm:ss`，左右为 MM / SS 两行 |

文本折行（与 Python `_mk_label` 的 `wraplength` 一致）：

- 横向 token 的 `wraplength = fpx × 1.5`，纵向为 `fpx × 1.7`
- 超过宽度按字符折行（CJK 无空格，等价于 Tk 对超长 word 的字符级折行）
- 折行后按"最宽行宽度 × 行数"参与布局；各行在块内水平居中，与 Tk Label 默认 `anchor=center` 一致
- 候选课程同样适用（所以"物/生/政""生史限时"等会显示为两行小块）

交互：

- 点按（位移 ≤3px）切换第二样式
- 拖动跨越屏幕 1/4 分界线切换停靠区，并套用该区"拖动默认样式"
- 拖到屏幕最外侧 5px 内（上/左/右）时**强制**该方向的 secondStyle（与 `class_frame.py`
  新版 `zone_of_drag` 一致）；在同一 dock 内移入/移出贴边带时样式也会跟着切换
- 拖动跟手使用非线性阻尼，窗口始终留在屏幕内，松手后弹性归位
- 编辑器中把候选课程拖到课表格子上即可替换，写入 `data.json`
- `<` / `>` 切换编辑器日期

调度：

- 1Hz 秒边界心跳驱动进度条、倒计时与状态切换
- 帧循环只在动画未收敛或交互期（含交互后保持时长）运行
- 位置动画收敛判定：`|目标-当前| < 0.5px` 且每帧位移 `< 0.05px` 时吸附并停止
- **窗口宽度与高度与位置、一起参与同一个弹簧动画**：切换停靠区或切换形态时，
  窗口从旧尺寸/旧位置逐渐过渡到新尺寸/新位置（与 Python 的 `movements` 一致）

## 3. 测试中发现并修复的问题

1. **时间解析错误**：`Json.minutesOf` 误对 `[21,30]` 这类时间对取了首元素，21:30 被当成 21 分钟，导致傍晚就判定"放学"。已修正。
2. **进度条被等比缩小**：纯进度条没有文字，不该按文字宽度缩放；改为按可用宽度收敛，厚度保持配置值。
3. **顶部被状态栏吃掉触摸**：`APPLICATION_OVERLAY` 窗口坐标系本身已排除状态栏，再叠加系统栏高度会把窗口推到 y=77，点按落空。已改为使用 `getMetrics()` 的应用可用区域，不再叠加 inset。
4. **data.json 过滤条件错误**：Python 统计的是"非 `|` 的 token 数"，之前误写成总长度，导致编辑器写入的记录会被过滤。已修正。
5. **打开应用不重启服务**：服务被回收后再次打开应用不会拉起悬浮层，已在 `onResume` 补上。
6. **多字 token 未折行**：原版对每个 token 设了 `wraplength`，横向 `fpx×1.5`、纵向 `fpx×1.7`，超宽即折行；先前只按单行测量，导致长课名排成一行、整行偏宽。已补上折行测量与多行绘制（含候选课程与纵向下课提示）。
7. **尺寸渐变动画看不见**：窗口几何本身一直在做弹簧动画（实测 `358x128 → 367x70 → 372x40`），但 View 只按"新内容尺寸"绘制，窗口多出来的部分是透明的，所以视觉上黑块直接跳到新大小。已改为 View 填满窗口、背景铺满，内容按新布局锚定左上角——与 Tk 窗口（黑底铺满整个窗口）的表现一致。
8. **尺寸过渡时闪烁**：逐帧调用 `updateViewLayout` 改变窗口尺寸会让某些帧在 surface 重建期间什么都画不出来（连拍实测 8 帧中 1 帧全空）。已改为：窗口尺寸只在形态切换时取"新旧内容较大值"调整一次，动画期间窗口不再逐帧 resize，改由 View 内部按动画尺寸绘制黑块并裁剪内容；动画停止 700ms 后再把窗口尺寸收回内容尺寸（视觉无变化）。修复后两个方向的过渡均为 0/8 空帧。
9. **向左右拖时窗口"被钉在另一侧"**：窗口尺寸取"新旧较大值"后会比屏幕宽，`WindowManager` 会把超出屏幕的窗口自行钳回屏内；而黑块锚在窗口左上角，于是黑块被带到错误位置（实测动画值 pos=185 时窗口实际被钳到 x=42），等窗口收缩到最终尺寸不再被钳制，才"闪"到正确位置。已改为由我们自己把窗口位置钳进屏幕，并把"可见矩形相对窗口的偏移"交给 View 绘制补偿。修复后中心→右侧的过渡：黑块左边缘 `21 → 95 → 354`；右→中心：`360 → 95 → 21`，均为连续移动。
10. **弹性起始点用错尺寸**：跨区时应把"目标区域静止时窗口的中点"作为橡皮筋起始点（Python 用 `preview_size(zone, style)` 算目标尺寸）。Android 版此前用的是**切换前的旧尺寸**，例如上方横条（374 宽）拖到左侧时，用 374 去算左侧中点，得到的点落在屏幕中央附近——恰好就是窗口当时的实际中点，于是 `dx≈0`、弹性消失，窗口直接贴到目标位置。已改为"先按新 dock/样式重建拿到目标尺寸，再算参考点"，实测：上→左 `ref=27,449`（左侧中点）、目标 `goal=38,187`（被拉向右）；左→上 `ref=200,33`（上方中点）、目标 `goal=0,71`（被拉向下）。
11. **倒计时窗口与主窗口尺寸不一致**：原设计约束是"左右停靠两窗等宽、上方停靠两窗等高"（Python 里竖向 `w = edge_text_geom[0]`，横向共用同一个 `fpx`）。Android 版有两处偏差：一是"超宽等比缩小"是每个窗口各自算的，主课表被缩 0.63 倍而倒计时没缩，导致数字显得更大；二是竖向宽度用了 `max(自然宽度, 主窗宽度)` 会把窗口撑得比主窗更宽。已改为**缩放系数由主窗口决定并共享给倒计时**、竖向宽度**严格等于**主窗宽度（数字更宽则裁掉）、横向高度**严格等于**主窗高度（文字垂直居中）。修复后上方 `358×40` / `82×40`，左侧 `39×567` / `39×90`，并且同组两窗不再重叠。
12. **倒计时消失动画冻结**：Python 的 `del_isl` 把目标尺寸设成 1×1（位置目标不变），窗口会原地逐渐缩小再销毁。Android 版同样设了 1×1，但 `syncAnimatedSize()` 只同步 `mainView` / `countView` 两个引用，而删除时 `countView` 已被置空——那个正在缩小的窗口再也收不到"当前可见矩形尺寸"，画面冻结在最后一帧、收敛后被直接移除（表现为"大小不变地瞬间消失"）。已改为遍历所有 island（含正在删除的）同步可见尺寸。实测删除期间可见尺寸连续变化：`82×40 → 79×39 → 75×37 → … → 23×12 → 1×1`。

## 4. 已知限制（属于 M3 范围）

- 放学 10 分钟后不会自动隐藏、次日课前 1 小时不会自动出现（需要 M3 的调度引擎与闹钟）
- 进程被杀后没有恢复机制（看门狗在 M3）
- 悬浮层位置与样式在进程重启后不保留
- 字体仍为系统无衬线体，内置圆体在 M4 加入

## 5. 手动验证建议

1. 打开应用 → 悬浮层出现在屏幕上方
2. **点一下悬浮层** → 在"整行文字"和"细进度条"之间切换
3. **按住悬浮层拖动**：向左/右/下拖过屏幕 1/4 分界线 → 停靠位置与排版方向随之改变，松手后弹性归位
4. 拖到屏幕中央 → 显示"进度条 + 时钟 + 课表"；再点一下 → 进入编辑器
5. 在编辑器里把候选课程拖到课表格子上 → 该课被替换并写入 `data.json`
6. 点 `<` / `>` → 日期前后切换
