# 时间校准（设备时钟错位）

教室机器的系统时钟可能差几分钟到几个月。app 不改系统时间（没有 `WRITE_SETTINGS`，也不该动别人的机器），
而是把"设备时钟错了多久"算成一个秒级偏移，供全部时间逻辑使用。

## 语义

```
校准后的时间 = 设备时间 + 时间偏移（秒）
```

- 正数 = 设备慢了，要往前拨；负数 = 设备快了，要往回拨。
- 偏移存在 `config.json` 的 `「时间偏移（秒）」`，与 Python 版、导入导出共用同一份数据，不另立一套。
- 范围是 Java `int`（±68 年），几个月、几年都放得下；内部换算用 `long`。
- 与设备时区无关：NTP / HTTP 拿到的都是真实 UTC 时刻，差值就是时钟误差本身。

## 时区

设置项默认 `Asia/Shanghai`。`Application.onCreate` 里用 `TimeZone.setDefault()` 设为进程默认时区，
因为所有取时间的地方都是 `Calendar.getInstance()`，改默认时区即全局生效。
可下拉选择，也可手动输入 ID（如 `GMT+08:00`）。

## 手动校准

system 页 →「时间校准」：

- **手动校准（秒）**：直接填偏移。支持负数（几个月到几十年的差值）。
- **按当前时间自动解算**：填"此刻真正是几点"，程序反解偏移。支持
  `yyyy-MM-dd HH:mm:ss`、`yyyy-MM-dd HH:mm`、`MM-dd HH:mm:ss`、`HH:mm:ss`、`HH:mm`
  五种写法（只写时刻时按"离现在最近的那一天"解释，所以设备差半天以内也能用）。
- 两栏**双向联动**：改任一个，另一个立刻更新，并显示"本机时间 → 校准后时间"对照。

## 自动更新

开关默认**关闭**。打开后：

| 触发时机 | 说明 |
| --- | --- |
| app 启动 | 后台线程同步一次 |
| 悬浮层服务启动 | 开机自启的机器没人开界面也能对时 |
| 服务常驻期间 | 每小时重试一次 |

十分钟内的重复触发会被去重。**失败只记日志并保留原偏移**，绝不会写入 0 或半截值。

### NTP

地址填主机名或 IP，端口默认 123，也接受 `host:port` 写法（默认 `ntp.aliyun.com`）。
标准 48 字节 SNTP 请求，用发送/接收时刻做往返补偿，避免高延迟下差几百毫秒。

### HTTP

分别填地址与端口（默认 `www.baidu.com:80`），地址也可以直接写完整 URL。
读响应头的 `Date`（RFC 1123，GMT，秒级精度）。连接失败会自动换另一种协议再试，
因为很多站点只有 https、而 http 会 301/302。优先 HEAD，服务器不给 `Date` 时退化为 GET。

## 实现位置

- `data/TimeSync.java`：偏移读写、时区、NTP / HTTP 取时、自动同步与重试
- `data/Prefs.java`：时区、自动更新开关与方式、地址端口
- `App.java` / `OverlayService.java`：启动时应用时区并触发自动同步
- `ui/SystemPage.java`：「时间校准」对话框
- `AndroidManifest.xml`：新增 `INTERNET`（NTP 与 HTTP 都需要）

## 边界

- 校准只影响 app 内部的时间计算，**不会改系统时钟**，所以截图时间、文件时间戳仍是设备时间。
- "按日期覆盖课表"（`data.json`）与 edit 页日期选择器仍以设备日期为准。设备日期本身错出月份时，
  在错误日期上录入的覆盖在时间校正后会对不上那天——这是设备日期错误的必然结果。
- 手动填入的时刻若是"几个月前/后"，HTTP 通道的秒级精度足够；追求毫秒级请用 NTP。
